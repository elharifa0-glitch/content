# استوديو الشغل

نسخة الموقع دي بتشتغل من أي جهاز أو موبايل، بحساب دخول حقيقي وقاعدة بيانات، من غير الاعتماد على أي مفتاح API خارجي — كل ميزات الذكاء الاصطناعي اتشالت والموقع دلوقتي معتمد على البيانات اللي بتدخلها إنت بنفسك.

الخطوات محتاجة حوالي 15-20 دقيقة أول مرة، وبعدين الموقع هيفضل شغال لوحده.

## الخطوة 1: اعمل حساب Supabase (قاعدة البيانات + تسجيل الدخول)

1. روح على [supabase.com](https://supabase.com) واعمل حساب مجاني.
2. دوس **New Project**.
3. اختار اسم للمشروع وباسورد لقاعدة البيانات (احفظه في مكان آمن).
4. استنى دقيقتين لحد ما المشروع يخلص إعداد.

## الخطوة 2: جهّز جدول البيانات ونظام الاشتراك

1. من القايمة الجانبية جوا Supabase، دوس **SQL Editor**.
2. دوس **New query**.
3. افتح ملف `supabase-schema.sql` اللي جوا المشروع ده، انسخ **كل** اللي فيه (فيه جزئين: جدول البيانات، وتحته جدول الاشتراكات)، والصقه في المحرر.
4. دوس **Run**.

ده هيعمل جدولين:
- `user_data` — بيانات كل مستخدم (البراندات والأفكار)، محدش يقدر يشوف بيانات حد تاني.
- `subscriptions` — بيتابع حالة اشتراك كل مستخدم، وبيدّي تلقائيًا تجربة مجانية 14 يوم لأي حساب جديد.

**لو عندك مستخدمين اتسجلوا قبل كده (زيك إنت):** في آخر ملف الـ SQL فيه سطرين معلّقين (`-- insert into...`) — شيل التعليق عنهم (احذف الـ `--` من الأول) وشغّلهم لوحدهم مرة واحدة، عشان يتعمل ليك ولأي حد اتسجل قبل كده سجل تجربة مجانية.

## الخطوة 3: فعّل تسجيل الدخول بالإيميل

1. من القايمة الجانبية، روح **Authentication > Providers**.
2. تأكد إن **Email** مفعّل (بيكون مفعّل افتراضيًا).
3. لو عايز تجرب بسرعة من غير ما تتأكد من الإيميل كل مرة: روح **Authentication > Settings**، وقفّل **Confirm email**. (تقدر ترجعها تاني بعدين لو الموقع هيبقى عام لناس كتير.)

## الخطوة 4: خد بيانات الاتصال

1. روح **Project Settings > API**.
2. هتلاقي **Project URL** و **anon public key** — انسخهم.

## الخطوة 5: جهّز المشروع على جهازك

محتاج [Node.js](https://nodejs.org) متثبت على جهازك (نسخة 18 أو أحدث).

```bash
# جوا فولدر المشروع
cp .env.example .env
```

افتح ملف `.env` اللي اتعمل والصق فيه القيم اللي نسختها من الخطوة 4:

```
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGc...
```

بعدين:

```bash
npm install
npm run dev
```

هيفتحلك لينك زي `http://localhost:5173` — افتحه في المتصفح، اعمل حساب، وجرّب الموقع محليًا الأول قبل النشر.

## الخطوة 6: انشر الموقع على Vercel (مجاني)

1. اعمل حساب على [vercel.com](https://vercel.com) (تقدر تسجل دخول بحساب GitHub مباشرة).
2. ارفع فولدر المشروع ده على [GitHub](https://github.com) (لو مش عارف تعمل ده، قولّي وهوريك خطوة بخطوة).
3. جوا Vercel، دوس **Add New > Project**، واختار الـ repo اللي رفعته.
4. قبل ما تدوس Deploy، افتح **Environment Variables** وضيف نفس المتغيرين من ملف `.env`:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. دوس **Deploy**.

بعد دقيقة أو اتنين هيديك لينك زي `your-project.vercel.app` — ده الموقع بتاعك شغال أونلاين، تقدر تفتحه من أي جهاز أو موبايل.

### مهم جدًا: اربط الدومين بتاعك بـ Supabase

بعد ما يبقى عندك لينك Vercel النهائي، لازم تروح تسجّله في Supabase وإلا **رابط تأكيد الإيميل عند التسجيل هيديله 404** (الحساب بيتفعّل فعليًا، بس المستخدم بيشوف صفحة خطأ بدل ما يرجع للموقع):

1. روح Supabase > **Authentication** > **URL Configuration**.
2. في **Site URL**، حط لينك Vercel بتاعك بالظبط (مثلاً `https://your-project.vercel.app`، من غير `/` في الآخر).
3. في **Redirect URLs**، ضيف نفس اللينك (وممكن تضيف `https://your-project.vercel.app/**` كمان عشان يغطي أي صفحة تحته).
4. احفظ.

لو الأداة كانت شغالة قبل كده على لينك تاني أو Site URL كان لسه على القيمة الافتراضية، ده هو سبب الـ 404 اللي بيحصل مع روابط تأكيد الإيميل.

### ملف vercel.json

المشروع فيه ملف `vercel.json` بيقول لـ Vercel إنه يوجّه أي رابط (بما فيه روابط التأكيد والتفعيل) لصفحة الموقع الرئيسية بدل ما يديله 404 — ده جزء تاني من نفس الحل، وميحتاجش أي تعديل منك، بس لازم يكون موجود في نفس فولدر المشروع وقت الرفع على Vercel.

بعد التعديلين دول (Site URL + `vercel.json`)، المستخدم لما يدوس على رابط التأكيد في الإيميل هيشوف شاشة "تم تفعيل حسابك بنجاح" بدل ما يشوف 404.

## يشتغل كـ "تطبيق" على الموبايل (PWA)

الموقع بقى فيه إعدادات PWA — يعني المستخدم يقدر يضيفه لشاشة موبايله ويفتحه بأيقونة زي أي تطبيق عادي (من غير Google Play أو App Store، ومن غير أي تكلفة).

### أول مرة بعد التحميل، لازم:

```bash
npm install
```

ده هيثبّت مكتبة `vite-plugin-pwa` الجديدة اللي مضافة في `package.json`.

### إزاي المستخدم يضيف الأيقونة؟

**على أندرويد (كروم):** بيفتح الموقع، هيظهرله تنبيه "إضافة إلى الشاشة الرئيسية" تلقائي، أو من قايمة المتصفح (⋮) يختار **Add to Home screen**.

**على آيفون (سفاري):** بيفتح الموقع في Safari، يدوس زرار المشاركة (المربع وعليه سهم لفوق)، ويختار **إضافة إلى الشاشة الرئيسية**.

بعد كده الأيقونة هتظهر على شاشته الرئيسية، وبتفتح بدون شريط عنوان المتصفح — حاسة زي تطبيق حقيقي.

### الأيقونات

الأيقونات جاهزة في فولدر `public/` (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`) بألوان البراند بتاعك. لو عايز تغيّرها بلوجو مختلف، استبدل الملفات دي بنفس الأسماء والمقاسات.

### لو عايزه فعلي في Google Play / App Store بعدين

ده خطوة تانية مختلفة (محتاجة حساب مطور مدفوع، وأدوات زي Capacitor لتغليف الموقع كتطبيق حقيقي). قولّي لو وصلت للمرحلة دي وهساعدك.

## لينك مشاركة للعميل

من صفحة أي براند، دوس على أيقونة المشاركة (🔗) جنب اسم البراند، وهتقدر تنشئ لينك تبعته لعميلك. اللينك ده:

- **مش محتاج تسجيل دخول** — أي حد معاه اللينك يقدر يفتحه.
- **بيوري بس**: اسم البراند، المحتوى الجاي والمنشور، وعدد المشاهدات لو مسجلة.
- **مبيوريش خالص**: أي بيانات مالية، مصاريف، أو براندات تانية.

تقدر تلغي اللينك في أي وقت من نفس الشاشة، وهيوقف يشتغل على طول.

**محتاج تشغّل SQL جديد قبل ما تستخدم الميزة دي** — شوف قسم "الخطوة 2" فوق، الجزء الخاص بـ `brand_shares`.

## تقرير PDF قابل للتخصيص

من تاب "تحليل البراند"، زرار "استخرج تقرير كامل" بقى يفتحلك اختيار الأقسام اللي عايزها في التقرير (نظرة عامة، الأداء، الوضع المالي، إلخ)، وتقدر:

- **تنسخ** التقرير كنص
- **تنزّله** كملف نصي
- **تنزّله PDF** جاهز تبعته لعميلك مباشرة

**ملحوظة مهمة**: المصاريف والربح الصافي بتاعك **مبيتحطوش في التقرير خالص** حتى لو فعّلت قسم "الوضع المالي" — دي بيانات داخلية بس ليك، والتقرير بيوري بس الإجمالي المتفق عليه والمستلم، عشان تحافظ على خصوصية هامشك.

## نظام الاشتراك (Paywall)

أي حساب جديد بياخد **تجربة مجانية 14 يوم** تلقائي (وفترة التجربة مش بيتطبق عليها حد عدد براندات — المستخدم يقدر يجرب كل حاجة). بعد ما تخلص، المستخدم بيشوف شاشة اشتراك بدل الموقع، فيها 3 باقات:

| الباقة | عدد البراندات | السعر الشهري | السعر السنوي |
|---|---|---|---|
| Starter | لحد 2 | 199 جنيه | 1,990 جنيه |
| Pro | لحد 5 | 399 جنيه | 3,990 جنيه |
| Unlimited | من غير حد | 699 جنيه | 6,990 جنيه |

كل الباقات فيها كل ميزات الأداة — الفرق بس في عدد البراندات المسموح بيه، وده **مطبّق فعليًا في الكود** (لو حد وصل لحد باقته، هيشوف رسالة ترقية الباقة بدل ما يقدر يضيف براند جديد).

لو عايز تغيّر الأسعار أو حدود البراندات، عدّل في مكانين:
- `PLANS` في `src/Paywall.jsx` (الأسعار المعروضة للمستخدم)
- `PLAN_LIMITS` في `src/ContentStudio.jsx` (الحد الفعلي المطبّق، القيم فيه لازم تتطابق مع أسماء الباقات: `starter`, `pro`, `unlimited`)

### قبل ما تنشر، لازم تعدّل في `src/Paywall.jsx`:

- **رقم الواتساب**: غيّر `whatsappNumber` (حط رقمك بصيغة دولية من غير `+` أو صفر في الأول، مثال: `201001234567`).
- **بيانات الدفع**: غيّر رقم الفودافون كاش/InstaPay بتاعك، ولينك الدفع الدولي لو عندك واحد (Payoneer، Wise، أو رابط دفع من Stripe/Paddle لو عملت حساب فيهم بعدين).

### إزاي تفعّل مستخدم دفع؟

1. روح لوحة Supabase > **Table Editor** > اختار جدول `subscriptions`.
2. دوّر على المستخدم (بالـ `user_id` — تقدر تلاقيه من جدول `auth.users` بالإيميل).
3. غيّر عمود `status` من `trial` لـ `active`.
4. غيّر عمود `plan` لواحدة من: `starter` أو `pro` أو `unlimited` (بالظبط بالحروف الصغيرة دي)، حسب الباقة اللي دفعها.
5. حط تاريخ في عمود `current_period_end` (مثلاً بعد شهر من دلوقتي، أو بعد سنة لو اشترك سنوي). لو سبته فاضي، الاشتراك هيفضل شغال من غير تاريخ انتهاء — يبقى لازم تدخل تاني بعد المدة تجدده أو تسيبه مفتوح حسب اتفاقك مع نفسك.
6. احفظ. المستخدم هيقدر يدخل تاني بمجرد ما يدوس "اتفعّل حسابي، جرب تاني" في شاشة الاشتراك، أو يعمل refresh للصفحة.

ده كله من غير أي كود إضافي — كل حاجة من واجهة Supabase.

### أكواد الخصم / التفعيل

المستخدم دلوقتي يقدر يفعّل حسابه بنفسه بكود، من غير ما تتدخل إنت — سواء وهو محظور من الاستخدام (شاشة الاشتراك)، أو حتى وهو لسه في تجربته المجانية.

**إزاي تعمل كود جديد:**

1. روح Supabase > **Table Editor** > جدول `redeem_codes`.
2. دوس **Insert row** واملا:
   - `code`: الكود نفسه، مثلاً `LAUNCH30` (المستخدم هيكتبه زي ما هو، حروف كبيرة أو صغيرة براحتك بس خليه ثابت).
   - `days`: عدد الأيام اللي الكود بيضيفها (مثلاً `30` لشهر مجاني).
   - `max_uses`: لو عايز الكود يتستخدم مرة واحدة بس حط `1`، أو سيبه فاضي لعدد استخدامات مفتوح.
   - `expires_at`: تاريخ انتهاء صلاحية الكود (اختياري، سيبه فاضي لو مفيش تاريخ معين).
   - `note`: ملاحظة لنفسك بس (مثلاً "كود المؤثر أحمد")، المستخدم مش بيشوفها.
3. احفظ. الكود شغال على طول.

**إزاي المستخدم بيستخدمه؟**
بيكتبه في خانة "عندك كود تفعيل أو خصم؟" في شاشة الاشتراك، ولما يدوس "فعّل"، النظام بيتحقق من الكود ويضيف الأيام تلقائي لحسابه — من غير ما يقدر يستخدم نفس الكود مرتين، ومن غير ما يقدر "يخترع" كود مش موجود (الفحص بيحصل جوا قاعدة البيانات نفسها، مش في كود الموقع اللي أي حد يقدر يشوفه).

**عايز توقف كود شغال؟** ارجع لنفس الصف في `redeem_codes` وغيّر `active` لـ `false`.

**ملحوظة:** الكود بيدّي وصول كامل (زي باقة Unlimited) للمدة المحددة، من غير قيد على عدد البراندات — مناسب كهدية أو كود تجربة موسّعة. لو عايز كود يدّي باقة معينة بعدد براندات محدود، قولّي وأضيفها.

### لما يزيد عدد المشتركين

لو الموضوع كبر وبقى صعب إنك تتابع كل حاجة يدوي، وقتها يبقى منطقي تدمج بوابة دفع حقيقية (Paymob للمصريين، Stripe أو Paddle للدوليين) تشتغل أوتوماتيك. قولّي وقتها وهساعدك تضيفها.



**هل الداتا هتفضل موجودة لو مسحت الكاش أو غيّرت جهاز؟**
أيوه — الداتا كلها بقت في قاعدة بيانات Supabase مش في المتصفح، فتقدر تدخل من أي جهاز بنفس الإيميل والباسورد وتلاقي كل حاجة موجودة.

**هل ده مجاني؟**
Supabase وVercel عندهم باقة مجانية سخية كفاية لاستخدام شخصي أو لعدد صغير من المستخدمين. لو الاستخدام كبر جدًا ممكن تحتاج تدفع، بس مش متوقع ده يحصل قريب.

**هل أقدر أضيف الذكاء الاصطناعي تاني بعدين؟**
أيوه، لكن هيحتاج شغل إضافي (سيرفر صغير وسيط يحمي مفتاح الـ API بتاعك، بدل ما يتحط في كود الموقع مباشرة). قولّي لو عايز تضيفها بعدين وهساعدك.

**نسيت الباسورد بتاعي؟**
خاصية "نسيت الباسورد" شغالة بالفعل من صفحة تسجيل الدخول.

**بيانات مين اللي بتتفعّل الاشتراك بتاعها بيدي؟**
تقدر تلاقي كل المستخدمين وحالة اشتراكهم من Supabase > Table Editor > `subscriptions`. راجع قسم "نظام الاشتراك" فوق.
